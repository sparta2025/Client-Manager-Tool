# Функциональность CRM юриста

## Назначение

CRM помогает юристу вести обращения клиентов от первого контакта до закрытия дела. В одном месте доступны список клиентов, статусы, журнал работы, контрольные даты, срочность и AI-помощники.

## Главная страница

На главной странице отображаются:

- общее количество дел;
- количество новых обращений;
- количество дел в работе;
- количество завершённых дел;
- таблица клиентов с контактами, статусами и датами;
- кнопка добавления нового дела;
- кнопка перехода в документацию.

Строка клиента открывает подробную карточку дела. Статус можно изменить прямо в таблице:

- `Новый` (`new`) — обращение ещё не взято в работу;
- `В работе` (`in_progress`) — по делу ведётся работа;
- `Закрыт` (`closed`) — работа завершена.

## Работа с клиентами

### Создание дела

Кнопка **«Новое дело»** открывает форму. Обязательные поля:

- ФИО клиента;
- контактный телефон.

Новое дело создаётся со статусом `new`.

### Редактирование

Для клиента можно изменить:

- ФИО;
- телефон;
- статус;
- дату обращения;
- дату закрытия обращения.

При переводе дела в статус «Закрыт» дата закрытия заполняется автоматически, если она не задана. При возврате в другой статус дата закрытия очищается.

### Удаление

Удаление требует подтверждения. Вместе с клиентом удаляются связанные этапы журнала дела.

## Карточка клиента

В карточке отображаются:

- контактная информация;
- текущий статус;
- дата обращения и дата закрытия;
- статистика по этапам;
- последний план работы;
- журнал этапов в хронологическом порядке.

### Этап журнала

Этап может содержать:

- название;
- дату этапа;
- содержание работы;
- результат;
- отметку выполнения;
- причины отказа или проблем;
- следующие планы;
- признак срочности;
- текущую контрольную дату;
- следующую контрольную дату;
- дату закрытия этапа.

Для закрытого клиента карточка доступна только для чтения. Добавление и изменение этапов для него недоступны.

## AI-помощники

AI-функции запускаются вручную из карточки клиента и используют бесплатный роутер `openrouter/free` через OpenRouter. При необходимости модель можно переопределить переменной `OPENROUTER_MODEL`.

### Агент-помощник юриста

Доступен для клиентов со статусом **«Новый»** по кнопке **«Составить план дела»**.

Он формирует предварительный план:

- краткое введение;
- от 3 до 6 последовательных этапов;
- ориентировочные даты;
- содержание каждого этапа;
- текущую и следующую контрольные даты;
- срочность;
- дальнейшие планы.

Сгенерированный план сначала показывается пользователю. Этапы попадают в журнал только после нажатия **«Сохранить в журнал»**.

### Агент-секретарь

Доступен для клиентов со статусом **«В работе»** по кнопке **«Проверить сроки»**.

Он анализирует незавершённые этапы и находит:

- просроченные контрольные даты;
- срочные этапы;
- контрольные даты в ближайшие 7 дней.

Результат содержит краткий заголовок, приоритет и список конкретных напоминаний. Закрытые клиенты не получают новые AI-напоминания.

## API

API-сервер работает под префиксом `/api`.

### Клиенты

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/api/clients` | Список клиентов |
| `GET` | `/api/clients/summary` | Сводка по статусам |
| `POST` | `/api/clients` | Создание клиента |
| `PATCH` | `/api/clients/:id` | Изменение клиента |
| `DELETE` | `/api/clients/:id` | Удаление клиента вместе с этапами |

### Журнал этапов

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/api/clients/:clientId/stages` | Этапы клиента |
| `POST` | `/api/clients/:clientId/stages` | Создание этапа |
| `PATCH` | `/api/stages/:id` | Изменение этапа |
| `DELETE` | `/api/stages/:id` | Удаление этапа |
| `GET` | `/api/clients/:clientId/stats` | Статистика по этапам |

### AI

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `POST` | `/api/ai/clients/:clientId/preliminary-plan` | Предварительный план для нового клиента |
| `GET` | `/api/ai/clients/:clientId/secretary-review` | Проверка сроков и срочности |

Контракт API хранится в `lib/api-spec/openapi.yaml`. После изменений в OpenAPI необходимо запускать кодогенерацию типов и хуков.

## Хранение данных

Используется PostgreSQL через Drizzle ORM.

Основные таблицы:

- `clients` — клиенты и основные данные дела;
- `case_stages` — этапы журнала, сроки и планы.

Поле `case_stages.client_id` связано с `clients.id` с каскадным удалением.

## Важные ограничения

- AI не ставит диагнозов и не заменяет юридическую проверку специалистом.
- Предварительный AI-план нужно проверить перед сохранением в журнал.
- Бесплатная модель может отвечать медленно или временно возвращать ошибку; сервер выполняет один повтор для временных ошибок.
- Секрет `OPENROUTER_API_KEY` нельзя помещать в клиентский код или Markdown-документацию.
